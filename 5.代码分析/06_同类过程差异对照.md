# 同类过程差异对照

## 1. 比较方法

- 【代码事实】比较基于所提供 SQL 的静态文本、去注释/空白/编号后缀后的规范化结构，以及关键 SQL 键和事务位置；未执行数据库对象。
- 【合理推断】“同构”表示核心 SQL 结构一致，不代表表数据、DDL、索引、触发器或运行结果必然一致。

## 4. 阶段2 PLIS01～13

### 4.1 共同骨架

- 【代码事实】全部过程都：解析 `YYYYMM` 月末、追加非零月度明细到编号历史表、循环历史时间点标记累计结零、生成五档当批表、循环账龄档组合结零并回写历史、写日志。
- 【代码事实】全部过程的预结零键、最终非零组键和跨档结零键宽度不一致；全部使用精确零；全部没有同月清理。
- 【代码事实】全部把月末结果保存到 `VARCHAR2`，且日期游标延伸到 `SYSDATE`。

## 7. 日志差异

- 【代码事实】阶段1 PLIS 完成描述仍写状态 `START`；这是确定的可观测性错误。证据：PLIS01 `:55`，其他12个同类位置。
- 【代码事实】阶段3 PLIS/AGS 的 START 使用分支专用方法名，但 END/ERROR 使用通用 `procedure_Aging_analysis`。证据：PLIS汇总 `:6-8,:891-893`；AGS汇总 `:8-10,:204-206`。
- 【代码事实】阶段1 GLIS 不写 `course_method_log`。证据：GLIS阶段1全文 `:1-115`。
- 【合理推断】若调度监控按方法名+状态判定成功，以上差异会造成无法闭环或错误归属；需结合实际监控查询确认影响。

## 8. 可模板化建议

- 【合理推断】PLIS 13 个阶段1过程和 13 个阶段2过程适合改造成“机构配置表 + 单过程 + 批次号”的数据驱动实现，可减少分支漂移。
- 【合理推断】模板化前必须先冻结当前差异：PLIS01 的机构特例/序列/提交、PLIS13 的 `AAA`、各分支表名与物理分区策略。
- 【待业务确认】是否允许合并物理分表；若监管/性能要求必须分表，可先生成统一模板但保留独立过程壳。
