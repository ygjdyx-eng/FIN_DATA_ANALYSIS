# PROCEDURE_AGING_ANALYSIS_TEMPDATAPLIS0102

- 【代码事实】技术目的：把 PLIS01 月度明细追加到历史表，标记累计/跨档结零，并生成01五档当批账龄。
- 【合理推断】业务目的：保留未结往来并按账龄档供最终报表汇总。
- 【合理推断】最小示例：参数202504的月末是2025-04-30；凭证2025-01-31相差3个月，进入档2；同科目保单在截止点+100/-100会被标记2。

- 【代码事实】用途与接口：阶段 2 PLIS01，把月度明细追加到 01 历史表，做累计结零、账龄分档和跨档结零；参数是已确认正确的 `YYYYMM`。`LAST_DAY(TO_DATE(executemonth,'YYYYMM'))` 被存入 `VARCHAR2` 变量。证据：`:1,:7,:31`，调用脚本 `:22`。
- 【代码事实】顺序：写 START 日志 → 对细粒度 `SUM(amount)<>0` 的组追加历史表 → 从 2018-10 到当前系统月逐月首/末日预结零 → 生成 01 当批表 → 遍历 `TEMP_AGING_COMBIN` 做跨档结零并回写历史标记 → END 日志。证据：`:13-34,:41-172,:177-342,:347-350`。
- 【代码事实】关键字段/粒度：首次非零判断使用短名、期间、科目、账户、产品、保单、地区、险种、来源、产品新码和日期；NULL 键多用字符串 `'null'` 等值，日期直接等值。证据：`:114-153`。
- 【代码事实】账龄：`MONTHS_BETWEEN(月末,会计日期)` 小于 3/12/36/60 分别为档 1/2/3/4，否则档 5；边界值进入后一档，未来日期进入档 1。证据：`:231-236`。
- 【代码事实】结零：预处理按“科目+保单”精确 `SUM=0` 标记 2；最终非零分组明确注释掉地区；跨档结零按“地区+科目+保单”精确 `SUM=0` 标记 1。证据：`:159-168,:263-295,:302-337`。
- 【代码事实】事务/重跑：5 个静态 COMMIT 位置，其中日期循环和组合循环内各有 COMMIT；同月没有 DELETE/MERGE，重复执行会再次 INSERT。证据：`:155,:171,:296,:341,:350`。
- 【代码事实】分支差异：本过程历史 ID 使用通用 `sequence_temp_FINANCE_Aging_analysis`，且比多数分支在两次主 INSERT 后额外提交。证据：`:79,:155,:296`。
- 【合理推断】风险：日期经 DATE↔VARCHAR2 隐式转换受 NLS 影响；以 SYSDATE 展开全部历史日期导致回溯成本持续增长；宽窄不一致的结零键可能跨机构/账户/产品/币种相抵；同月重跑非幂等。
- 【代码事实】接口断点：阶段 1 的显式列清单未写本过程读取的 `LEDGER_ID/SHORT_NAME/PRODUCT_NO/SEGMENT6/PERIOD_NAME` 及多个人员/产品字段。除非 DDL 默认值或触发器补齐，否则为 NULL。证据：阶段1 PLIS01 `:11-36`；本过程 `:80-111`。
- 【待业务确认】提供中间表 DDL/触发器，确认累计结零键、币种维度、日期边界与重复执行策略。
