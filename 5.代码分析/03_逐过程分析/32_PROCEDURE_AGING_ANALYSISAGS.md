# PROCEDURE_AGING_ANALYSISAGS

- 【代码事实】技术目的：对 AGS 共享当批数据做资格组和细粒度两层汇总并追加最终表。
- 【合理推断】业务目的：按代理、产品、渠道等维度输出佣金未结账龄余额。
- 【合理推断】最小示例：某科目保单地区来源渠道资格组合计0时整组不写最终表；合计非0时再按更细代理/产品等字段分别汇总。

- 【代码事实】用途与接口：阶段 3 AGS，把共享当批佣金账龄汇总到 `FINANCE_AGING_ANALYSIS`；参数为正确的七位期间 `2025004`。证据：`:1`，调用脚本 `:40`。
- 【代码事实】控制流：记录 START；统计共享当批表所有来源的总行数；大于 0 时进行 AGS 汇总插入；最后记录 END 并 COMMIT。证据：`:8-25,:108-205,:211`。
- 【代码事实】两层粒度：内层资格组按科目、保单、地区、来源、渠道 `SUM<>0`；连接回 AGS 明细后，再按科目、账龄、地区、来源、机构、账户、代理人、保单、产品、渠道/分销等细字段汇总。证据：`:108-200`。
- 【代码事实】金额/机构/期间：金额为明细 SUM；机构取分支码前 9 位并查名称；`AGING_PERIOD` 直接写入 `executemonth`。证据：`:111-200`。
- 【代码事实】事务/重跑：无同期间清理或 MERGE，仅末尾提交；相同期间重复运行会再次 INSERT 或触发约束。证据：`:108-211`。
- 【代码事实】日志差异：START 使用 AGS 专用方法名，END/ERROR 字段使用通用 `procedure_Aging_analysis`。证据：`:8-10,:204-206`。
- 【合理推断】风险：资格组未含账户、产品、业务场景和币种，可能先跨细维度相抵；共享总行数条件不代表存在 AGS 行；重跑不幂等；日志归属不清。
- 【待业务确认】确认资格组粒度、AGS 连续账龄月在最终表的解释、币种及同期间重跑策略。
