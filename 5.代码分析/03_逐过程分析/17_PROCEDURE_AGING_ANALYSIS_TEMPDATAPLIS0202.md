# PROCEDURE_AGING_ANALYSIS_TEMPDATAPLIS0202

- 【代码事实】技术目的：维护 PLIS02 历史结零状态并生成02五档当批账龄。
- 【合理推断】业务目的：将 PLIS02 尚未结清的保单科目余额按账龄展示。
- 【合理推断】最小示例：202504对应月末2025-04-30；会计日期2024-04-30相差12个月，进入档3；同组净额0则不进入初始非零追加。

- 【代码事实】用途与接口：阶段 2 PLIS02；参数 `YYYYMM`，计算月末后存入 `VARCHAR2`；上游/下游为 02 月度、历史、当批三表。证据：`:1,:7,:31,:40,:175`，调用脚本 `:23`。
- 【代码事实】流程：非零细粒度组追加历史 → 按 2018-10 至 SYSDATE 的月首/月末循环标记累计结零 → 生成五档账龄 → 按配置档位组合结零并回写历史 → 记录结束。证据：`:13-27,:40-342`。
- 【代码事实】粒度/账龄/结零：初始组含短名、期间、科目、账户、产品、保单、地区、险种、来源、新产品码及日期；五档阈值 `<3/<12/<36/<60/其他`；预结零按科目+保单，跨档按地区+科目+保单，均精确 `SUM=0`。证据：`:113-152,:230-235,:157-170,:295-334`。
- 【代码事实】事务/重跑：3 个静态 COMMIT 位置，其中两个在循环；没有同月清理或 MERGE。证据：`:170,:334,:344`。
- 【代码事实】与 PLIS01 差异：使用编号历史序列；没有两次主 INSERT 后的额外 COMMIT，声明顺序略有差别，核心规则同构。证据：`:77-78,:152-175,:286-295`。
- 【代码事实】字段断点：阶段 1 只显式写 12 个业务字段，而本过程读取更多账簿、期间、产品/代理等字段；DDL 未提供。证据：阶段1 PLIS02 `:11-36`；本过程 `:79-108`。
- 【合理推断】风险：NLS 日期隐式转换、历史扫描随时间增长、非幂等、全局表并发、宽窄结零键和缺少币种均可能影响金额。
- 【待业务确认】验证 DDL 补值机制、零余额匹配粒度、单币种和重跑控制。
