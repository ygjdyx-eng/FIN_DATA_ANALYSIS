# BALANCE_OFF

- 【代码事实】技术目的：生成 PLIS/AGS/GLIS 零余额候选并从指定期间最终表物理删除匹配行。
- 【合理推断】业务目的：从最终账龄报表剔除按各分支核销规则已结清的往来。
- 【合理推断】最小示例：同保单机构的科目A合计0、科目B合计100时，当前PLIS第二次DELETE会因只匹配保单+机构而把B也删除；这正是R-001的最小复现场景。

- 【代码事实】用途与接口：阶段 4 对 `FINANCE_AGING_ANALYSIS` 执行各来源的零余额候选识别与物理删除；参数为正确的七位期间 `2025004`。证据：`:1-2`，调用脚本 `:44`。
- 【代码事实】流程：以无条件 DELETE 清空 `FI_AGING/FI_AGING01/FI_AGINGAGS/FI_AGING_GLIS` → 写 PLIS 两类候选并删除 → 写 AGS 一般/特殊候选并删除 → 写 GLIS 一般/特殊候选并删除 → COMMIT。证据：`:4-7,:10-103,:105`。
- 【代码事实】PLIS 确定问题：`FI_AGING01` 候选按“保单+机构+科目”汇总为零，但第二次 DELETE 只按“保单+机构”匹配，遗漏科目，因而同保单机构下其他非零科目也会被删除。证据：候选 `:23-34`，删除 `:48-49`。
- 【代码事实】AGS NULL 问题：一般候选把 NULL 保单写成 `'000'`，删除时却在两边用 `'null'` 比较；源 NULL 候选存为 `'000'`，不能匹配回源 NULL。证据：`:36-41,:53-55`。
- 【代码事实】AGS 特殊口径：注释列出 `2202010302/2202010207/2241010217`，实际 IN 列表只有后两项；特殊候选按科目+来源+代理人+账龄汇总，不含保单/机构/渠道。证据：`:62-73`。
- 【代码事实】GLIS 特殊口径：`2243010106` 候选只统计账户段 `1301`，DELETE 键却不包含账户段，因此匹配组内其他账户段也会被删除；一般规则排除该科目。证据：`:77-96`。
- 【代码事实】序列：两次 GLIS 候选 INSERT 使用 `sequence_FI_AGINGAGS`；是否为共享序列需 DDL 确认。证据：`:82,:91`。
- 【代码事实】事务/并发/重跑：开头四次清表是 DML DELETE，与后续写候选和删最终表在末尾统一 COMMIT；无异常处理，候选表为全局共享且无批次隔离。重复执行删除本身趋于幂等，但不能自动恢复误删。证据：`:4-7,:105-106`。
- 【合理推断】风险等级：PLIS 遗漏科目键可直接扩大删除范围，属高风险确定缺陷；AGS/GLIS 特殊键过宽可跨组织或账户删除；物理删除缺乏审计快照和回滚窗口。
- 【待业务确认】在修复/重跑前确认四类零余额业务主键、AGS 注释与代码的科目集合、GLIS 1301/1302 意图，并以生产副本量化受影响行。
